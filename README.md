# storage-aggregator (Куб)

Агрегатор складов по России — все виды, с делением на категории внутри
(`storages.category`): `self_storage` (мини-склады для частных лиц), `warehouse_rental`
(складские помещения в аренду), `logistics`, `wholesale`, `industrial`. Модель для
self_storage — как Booking: клиент ищет и бронирует бокс, площадка берёт комиссию
~6000 ₽ с брони со склада; для остальных категорий монетизация уточняется отдельно.
География — в первую очередь регионы (не Москва).

```
storage-aggregator/

├── scripts/                    # вспомогательные скрипты сбора (не часть основного пайплайна pipeline.py)
│   ├── count_cities.py         # подсчёт складов по городам, 1 запрос 2ГИС на город
│   ├── fetch_cities.py         # сборка полного cities.csv из GeoNames (нужен доступ в интернет)
│   ├── dump_cities_to_log.py   # разовый прогон fetch_cities.py на Railway с выводом CSV в лог деплоя
│   ├── dry_run_pipeline_to_log.py # разовый прогон pipeline.py --dry-run на Railway с выводом в лог деплоя

    ├── config.py                # чтение .env / переменных окружения
    ├── requirements.txt
    ├── db/
    │   ├── schema.sql           # таблицы storages, operator_sites
    │   └── connection.py        # подключение к Postgres, применение схемы
    ├── sources/
    │   ├── dgis.py              # клиент 2ГИС Places API (Каталог 3.0)
    │   └── yandex.py            # заглушка — пока не используется
```

## Переменные окружения

Скопируйте `.env.example` в `.env` (или задайте в Railway → Variables):

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения к Postgres (в Railway — `${{Postgres.DATABASE_URL}}`) |
| `DGIS_API_KEY` | ключ 2ГИС Places API (демо-ключ — 1000 запросов) |
| `ANTHROPIC_API_KEY` | ключ Claude API для краулера сайтов операторов |
| `MIN_POPULATION` | порог населения города для выборки из `cities.csv` (по умолчанию `100000`) |
| `DGIS_RADIUS_M` | радиус поиска вокруг центра города, метры (по умолчанию `15000`) |

## Список городов

`cities.csv` в репозитории — **145 городов России с населением от 100 тыс.** (от
Москвы, 10,4 млн, до Глазова, 100 676), собраны из GeoNames (`download.geonames.org`,
CC BY 4.0) через `scripts/fetch_cities.py` и прогнаны на Railway (в песочнице Claude
Code нет доступа к GeoNames — сетевая политика блокирует внешние хосты кроме
GitHub/PyPI/npm). Названия городов и регионов — вручную на правильный русский (см.
ниже, почему автоматически не вышло); население/координаты — как есть из GeoNames.

Один населённый пункт (Черёмушки, Москва, geonameid с feature_code района внутри
Москвы) исключён вручную — это район, а не отдельный город, задвоил бы Москву.

Чтобы расширить список ниже 100 тыс. или пересобрать с нуля:

```bash
python scripts/fetch_cities.py --min-population 0 --out cities.csv
```

Полный список (без порога) — это ~1870 населённых пунктов (feature_code из
ADMIN_FEATURE_CODES — административные центры разного уровня), что отличается от
официальных 1117 «городов» Росстата — GeoNames классифицирует населённые пункты иначе,
чем российское законодательство. Запускать там, где есть доступ в интернет, тем же
способом (через Railway, как сделали мы — см. `scripts/dump_cities_to_log.py`) или
локально.

**Про названия:** поле `name` в GeoNames для российских городов — это английский
экзоним/транслитерация ("Moscow", не "Москва"), не кириллица. Автоматически переводить
это в правильное русское название оказалось опаснее, чем оставить как есть: единственный
опробованный способ (брать первое кириллическое имя из alternatenames) подхватывал
названия на осетинском/чувашском/марийском/якутском и советские исторические имена
(Москва → «Мæскуы», Пермь → «Молотов», Набережные Челны → «Брежнев»). Для нынешних 145
городов названия и регионы вписаны вручную. Для расширения списка (`--min-population 0`
или ниже 100 тыс.) новые строки будут с английскими названиями из GeoNames — поправить
через `scripts/city_name_overrides.csv` (`geonameid,city`) или вручную в `cities.csv`.

## Категории складов

Заданы в `storage-parser/config.py::SEARCH_CATEGORIES` — каждая категория это список
поисковых формулировок для 2ГИС (единой рубрики "склады" по всем городам нет, поэтому
ищем текстом):

| Категория | Формулировки |
|---|---|
| `self_storage` | мини-склад, индивидуальное хранение, хранение вещей, бокс-склад, склад временного хранения |
| `warehouse_rental` | склад в аренду, аренда складского помещения, складское помещение |
| `logistics` | логистический склад, склад ответственного хранения, распределительный склад |
| `wholesale` | оптовый склад, торговая база |
| `industrial` | промышленный склад, производственный склад |

Итого 15 формулировок — прогонять все по каждому городу дорого для демо-ключа, поэтому
план ниже сначала оценивает объём общим запросом, потом тестирует формулировки точечно.

### Разведка на живых данных (Казань, демо-ключ)

Прогнали `scripts/count_cities.py --all-queries` и `pipeline.py --dry-run` на Казани и выяснили
два реальных ограничения API, которых нет в официальной документации в свободном доступе:

- `page_size` — от 1 до 10 (не 50), `page` — от 1 до 5. То есть **максимум 50
  результатов на один текстовый запрос** через пагинацию этого эндпоинта — жёсткий
  потолок, не наша защита от лимита. Для категорий с 100+ реальных совпадений
  (например, self_storage/"бокс-склад" — 119) остальное этим способом не добрать.
- Текстовый поиск слабо различает наши формулировки: «склад временного хранения»,
  «склад в аренду» и «склад ответственного хранения» (три разные категории!) дают
  сильно пересекающиеся наборы результатов с заметным шумом — грузоперевозки, опт,
  стройматериалы. Выбирать «2 лучшие формулировки» по одним числам ненадёжно.

Зато нашли точный сигнал: у 2ГИС есть собственная рубрика **«Склады индивидуального
хранения»** — это и есть self-storage, дословно. Она встречается у настоящих
self-storage операторов (Домосклад, Складно, Твой склад, Serbox, Мега Склад)
**независимо от того, какой из наших запросов их нашёл** — например, по запросу
«склад в аренду» (категория warehouse_rental) среди находок оказалось много объектов
с этой рубрикой. `pipeline.py` теперь переклассифицирует по рубрике поверх текстового
запроса (`resolve_category()` в `pipeline.py`, `config.RUBRIC_CATEGORY_OVERRIDES`) —
это надёжнее, чем гадать по формулировкам. Для остальных категорий (warehouse_rental,
logistics, wholesale, industrial) отдельной рубрики не нашли — там пока только
текстовый поиск + `TITLE_EXCLUDE_KEYWORDS`.

**Бюджет демо-ключа с поправкой на потолок в 50 результатов:** полная выгрузка по
городу с 15 формулировками, когда большинство категорий упираются в потолок,
обходится не в ~2-3 запроса на формулировку (как думали изначально), а в среднем
3-5 запросов (оценка по факту — многие формулировки в Казани упёрлись в 50/50, то
есть все 5 страниц). На 145 городов (население от 100 тыс., полный список теперь в
`cities.csv`) это **значительно больше 1000 запросов демо-ключа**, если гнать все
15 формулировок по всем городам.
Практичный вариант — сначала решить, что реально нужно (видимо, в первую очередь
self_storage через рубрику, остальные категории — по минимуму формулировок), и/или
перейти на платный тариф 2ГИС до полного рывка по всем городам.

### Демо-ключ 2ГИС не отдаёт контакты (блокер для краулера)

Проверили сырой ответ API напрямую (`fields=items.point,items.address,items.contact_groups,items.rubrics`)
— поля `contact_groups` в ответе нет вообще, ни пустым массивом, ни с данными,
ни у одной организации. То есть ни телефона, ни сайта с демо-ключа не получить —
это ограничение тарифа 2ГИС, не баг в `dgis.py::_parse_item`. Следствие:
`operator_sites` будет оставаться пустой после реального (не `--dry-run`) прогона
`pipeline.py` — краулеру (`storage-parser/crawler/site_crawler.py`) нечего будет
забирать, пока не перейти на платный тариф 2ГИС с доступом к контактам, или не
прийти к доменам операторов другим путём (например, из будущей выгрузки Авито).

### Находка по шагу 1: подмосковные города завышают счёт

Общий запрос "склад" по подмосковным городам-спутникам даёт аномально высокие числа —
выше, чем у многих городов-миллионников: Люберцы 658, Химки 504, Мытищи 455, Балашиха
401, Королёв 319, Одинцово 306, Пушкино 156 (для сравнения: у Москвы самой — 891,
у Новосибирска, третьего по населению города России — 364). Причина — радиус поиска
15 км (`DGIS_RADIUS_M`) у соседних с Москвой городов перекрывает одну и ту же
промышленно-логистическую зону МКАД, то есть это не 7+ отдельных рынков складов,
а один и тот же московский пояс, посчитанный по многу раз. Раз фокус проекта — регионы,
не Москва (см. начало README), для финальной выгрузки стоит либо явно исключить Москву
и область, либо считать Москву с областью одним рынком, а не ~10 отдельными городами —
иначе треть бюджета демо-ключа уйдёт на дублирующиеся данные по одному региону.

## Деплой на Railway

Сервис подключён к проекту `storage-aggregator` (Postgres уже развёрнут там же).
`railway.json` в корне поднимает `server.py` — отдаёт `kubometr.html` как статический
прототип на сгенерированном Railway-домене. Скрипты `storage-parser/*.py` запускаются
разово через `railway run python storage-parser/pipeline.py ...` или Railway Cron —
это batch-джобы, не веб-сервер.

Переменные сервиса: `DATABASE_URL=${{Postgres.DATABASE_URL}}`, `DGIS_API_KEY`,
`ANTHROPIC_API_KEY`.

## Импорт Авито

У Авито нет официального API для массового сбора — выгрузка собирается вручную
(браузер / Claude в Chrome) в CSV по шаблону `avito_import_template.csv` и
импортируется `storage-parser/import_avito.py`:

```bash
cd storage-parser
python import_avito.py ../avito_import.csv --dry-run   # проверить без записи в БД
python import_avito.py ../avito_import.csv              # записать (source=avito)
python dedupe.py                                         # склеить дубли с 2ГИС (across source — без изменений)
```

Обязательные колонки шаблона: `city`, `url`, `name`. `url` — основа `source_id`
(берётся числовой id из конца ссылки вида `..._1234567890`, иначе md5 от url).
Авито часто даёт то, чего нет у демо-ключа 2ГИС — например, телефон продавца
(см. «Демо-ключ 2ГИС не отдаёт контакты» выше) — колонка `phone` в шаблоне.
`dedupe.py` уже работает по всем `source` в рамках города без изменений — отдельно
прогонять для Авито не нужно, просто гонять `dedupe.py` после каждого импорта.
